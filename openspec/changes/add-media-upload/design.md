## Context

Хранилище — MinIO (S3-совместимое), постоянное, без переезда в облако. Клиент — Flutter (dio), который после выбора фото из галереи/камеры отправляет файл.

## Decisions

- **Multipart через API, а не presigned upload.** Один запрос `dio FormData` вместо двух (получить подпись → PUT в хранилище). Не требует публичного доступа к MinIO на запись и CORS на бакете, работает одинаково на Flutter web/mobile. Размер ограничен (5 МБ), поэтому проксирование через API (память, multer) допустимо. Цена: трафик идёт через API — приемлемо для малой аудитории; при росте можно перейти на presigned, не меняя контракт `url` для остальных модулей.
- **Порт `StoragePort`** (`put`, `isOwnUrl`) в `storage/interface`; DI-токен `STORAGE`. Доменный код (`media`) не знает про MinIO. Реализация `S3StorageService` читает `S3_ENDPOINT`, `S3_BUCKET`, `S3_ACCESS_KEY`, `S3_SECRET_KEY`, `S3_PUBLIC_URL` (`S3_REGION`, `S3_FORCE_PATH_STYLE` — опционально) лениво через `requireEnv`: без них приложение стартует, а загрузка отвечает 503 `STORAGE_NOT_CONFIGURED`.
- **Проверка файла по содержимому** (magic bytes JPEG/PNG/WebP), а не по `Content-Type`/имени клиента; ключ строится на сервере (`images/<userId>/<uuid>.<ext>`), имя файла клиента не используется (нет path traversal, нет перезаписи).
- **Пакетная загрузка фото портфолио:** `POST /media/portfolio-images`, поле `files`, `FilesInterceptor('files', 5)` с memoryStorage (файлы ≤ 5 МБ × 5 = ≤ 25 МБ в памяти, стриминг в S3 не нужен; для dio — обычный `FormData` с несколькими `files`). Multer `fileSize` стоит на 1 КБ выше лимита, чтобы слишком большой файл доходил до сервиса и получал код `IMAGE_TOO_LARGE`, а не общий 413. Сервис до записи проверяет: число файлов ≤ свободных мест (5 − уже в портфолио, иначе 409 `PORTFOLIO_LIMIT_REACHED`), сумму ≤ 25 МБ (`IMAGES_TOTAL_TOO_LARGE`), каждый файл ≤ 5 МБ и тип по сигнатуре. «Учёт уже загруженных» реализован через число элементов портфолио (вес ранее сохранённых фото не хранится). Аватар — по-прежнему `POST /media/images`, один файл ≤ 5 МБ. Константы — в `media/media.constants.ts` (`MAX_IMAGE_BYTES`, `MAX_IMAGES_TOTAL_BYTES`, `MAX_PORTFOLIO_PHOTOS`); `MAX_PORTFOLIO_ITEMS` в social равен `MAX_PORTFOLIO_PHOTOS`.
- **Обработка изображений (`sharp`).** Все загрузки перекодируются в WebP (quality 80): поворот по EXIF, вписывание в 512 px (аватар, `POST /media/images`) или 1600 px (портфолио, `POST /media/portfolio-images`) без увеличения, метаданные (EXIF/GPS) не сохраняются. Плюсы: в разы меньше размер, приватность геометок, единый формат и ключ `.webp`. Лимиты 5 МБ / 25 МБ относятся ко входным файлам. `limitInputPixels` = 50 Мпикс защищает от «бомб»; битый файл — 400 `IMAGE_CORRUPT`. В пакете сначала обрабатываются все файлы, потом они записываются в хранилище. Клиент всё равно должен сжимать перед отправкой (`image_picker` `maxWidth`/`imageQuality`), чтобы не гонять 5 МБ по сети. Для одиночного фото портфолио использовать `/media/portfolio-images` с одним файлом (`/media/images` ужимает до 512 px).
- **Права:** `profiles:update_own` (есть у тренера и ученика): аватар нужен обоим, портфолио — только тренеру, и его лимит проверяется при создании элемента.
- **Публичное чтение.** Бакет с анонимным `download`; запись — только по ключам API. Caddy отдаёт `https://API_HOST/files/<bucket>/<key>` (`handle_path /files/*` → `minio:9000`), отдельный домен не нужен. `S3_PUBLIC_URL` = эта база.
- **Внешние ссылки остаются допустимыми** (https), чтобы не ломать существующие записи и ручной ввод. Валидатор `@IsMediaUrl()`: https-любой либо префикс `S3_PUBLIC_URL` (в dev он может быть http). CHECK в БД ослаблен до `^https?://`; допустимость адреса проверяет API.
- **Неиспользуемые объекты** (загрузили, но не сохранили профиль / удалили элемент) пока не удаляются; очистка — отдельная задача.
- **Лимит портфолио = 5** (`MAX_PORTFOLIO_ITEMS`), `409 { code: 'PORTFOLIO_LIMIT_REACHED' }`.

## Risks / Trade-offs

- Образы MinIO с октября 2025 не публикуются на Docker Hub; в compose образ параметризован (`MINIO_IMAGE`, `MINIO_MC_IMAGE`). Благодаря порту хранилище заменяемо.
- Контракт ответа — DTO `UploadedImageResponseDto`; в репозитории нет OpenAPI-генерации, отдельный codegen-артефакт не обновляется.
