## Why

Вкладка «Чаты» у тренера и «Чат» у ученика сейчас заглушка (`lib/features/chats/presentation/chats_page.dart`). Переносы и вопросы по тренировкам уходят в мессенджеры вне приложения, и тренер теряет контекст: что перенесли, когда, кто. Доски канваса «Чаты», «Переписка», «Чат ученика» уже готовы.

## What Changes

- Новый backend-модуль `chat` (`backend/api/src/chat/`): один диалог на пару тренер↔ученик, текстовые сообщения, счётчик непрочитанных, системные сообщения о событиях занятий (запись, отмена, перенос, ответ на заявку).
- Транспорт v1: REST + polling (короткий опрос только пока экран открыт). WebSocket и push не входят.
- Новые права `chat:read_own`, `chat:send_own` для ролей trainer и student.
- Flutter: экраны «Чаты» (список), «Переписка» (тред), «Чат» ученика вместо заглушки; бейдж непрочитанных на вкладке; кнопки «Написать» в карточке ученика и профиле ученика.

## Non-goals

- Push-уведомления (FCM/APNs) — отдельный поток, нужен для «пришло сообщение, приложение закрыто».
- Вложения (фото/видео), голосовые, редактирование и удаление сообщений, «печатает…», галочки «прочитано» у собеседника.
- Групповые чаты, чат в web-консоли тренера.

## Capabilities

### New Capabilities

- `chat-api`: диалоги, сообщения, непрочитанные, системные сообщения, права.
- `mobile-chat`: список диалогов, тред, чат ученика, бейдж, точки входа.

### Modified Capabilities

- (нет; хуки системных сообщений добавляются в сервисы sessions / booking-requests / recurring-bookings без изменения их контрактов)

## Impact

- Backend: модуль `chat`, 2 entity + миграция, seed прав, вызовы `ChatSystemMessageService` из `sessions`, `booking-requests`, `recurring-bookings` внутри их транзакций.
- Flutter: `lib/features/chats/` (data, cubit, presentation), роуты `/chats/:id`, бейдж в shell, кнопки «Написать».
- Тесты: unit + e2e API (права, непрочитанные, идемпотентность отправки, системные сообщения), widget-тесты экранов.
