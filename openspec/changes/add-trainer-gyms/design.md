## Данные

- `gyms(id, name ≤120, address ≤255, city ≤120, district ≤120 null, dedupe_key UNIQUE, created_at, updated_at)`.
- `trainer_gyms(coach_id → users, gym_id → gyms, created_at)`, PK `(coach_id, gym_id)`, индекс по `gym_id`, `ON DELETE CASCADE` с обеих сторон.
- `dedupe_key = lower(trim/collapse(name)) | … address | … city`, `ё → е`. Город входит в ключ: сети с одинаковым названием и типовым адресом («ул. Ленина, 1») в разных городах — разные залы. Это сознательное уточнение «название + адрес» из плана.
- Район хранится текстом. Если зал создан без района, а следующий тренер указал его — район дописывается; уже заданный не перезаписывается (чужой ввод не затираем).

## Создание и гонки

`POST /profiles/me/gyms` делает `INSERT … ON CONFLICT DO NOTHING` по `dedupe_key` и затем читает запись, поэтому два тренера, одновременно вводящие один зал, получают один `id`. Привязка идемпотентна (`ON CONFLICT DO NOTHING` по паре). Лимит — 10 залов на тренера (409).

## API

| Метод | Путь | Права | Заметка |
|-------|------|-------|---------|
| GET | `/profiles/me/gyms` | `profiles:update_own` + роль trainer | свои залы |
| POST | `/profiles/me/gyms` | то же | `{gymId}` либо `{name,address,city,district?}`; 201 |
| DELETE | `/profiles/me/gyms/:gymId` | то же | 204, 404 если не привязан |
| GET | `/gyms/suggestions?query&city&limit` | то же | подстрока названия/адреса, город; limit ≤ 20; LIKE-символы экранируются |
| GET | `/trainers?city&gymId&district&gymQuery` | `profiles:read_public` | см. ниже |

Подсказки отдают только поля зала (без списка тренеров), доступны тренерам: это общая база, но её содержимое не раскрывает, кто в каком зале занимается.

## Каталог

Фильтры зала применяются одним `EXISTS` по `trainer_gyms ⨝ gyms`, поэтому `gymId`, `district` и `gymQuery` проверяются на **одном и том же** зале тренера, а строки профиля не дублируются (агрегаты рейтинга не искажаются). `city` — `profile.city ILIKE` либо город любого из его залов. `gyms[]` в карточках подгружаются одним запросом на страницу (без N+1). Каталог и публичный профиль уже ограничены `is_discoverable`, поэтому залы скрытых профилей не раскрываются.

## Валидация

- Телефон: DTO `@Matches(/^\+7\d{10}$/)` на сыром вводе; сервис дополнительно проверяет нормализованное значение. Сырой ввод с пробелами/скобками больше не принимается — нормализует клиент.
- Специализации: DTO `@ArrayMaxSize(8)`, `@MaxLength(30, {each})`, сервис повторяет проверки после trim/lowercase. Хранение прежнее (`varchar[]`). Миграция: подрезает до 8 тегов и 30 символов, заменяет `CHK_user_profiles_specialties_count` (≤10) на ≤8; `down` возвращает ≤10.
