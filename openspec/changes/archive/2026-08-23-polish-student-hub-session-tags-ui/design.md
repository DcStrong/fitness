## Context

Сейчас хаб ученика — вертикальные секции «Ближайшие / Назначенные / Программа / Абонемент / Прогресс» одинаковыми `FyCard`. Страница занятия — лента `FySecondaryButton` + сырые `FilledButton`/`OutlinedButton` для lifecycle. Библиотека рисует **все** теги горизонтальным `FilterChip`. `/tags` — строка с корзиной.

Макеты: `app/design/generated/mock-student-hub-a-profile.png`, `mock-student-hub-b-actions.png`, `mock-session-a-one-cta.png`, `mock-library-tags-compact.png`, `mock-tags-as-groups.png`, `mock-tags-search-sheet.png`. Смысл экранов, не pixel-perfect.

Стек: Flutter Bloc/Cubit, существующие репозитории (`StudentHubCubit`, `SessionWorkoutCubit`, `PlansLibraryCubit`, `TagsCubit`). API не расширяем.

## Goals / Non-Goals

**Goals:**

- Хаб: человек сверху, неделя + программа, компактная сетка действий, тренировки с «Назначить», прогресс.
- Занятие: контент доминирует; один primary `FyButton`; состав/смена — текст; неявка/отмена/история — тихо или ⋯.
- Библиотека: 4–5 тегов + «Ещё» → шит поиска.
- Теги: карточки-группы, delete не в строке.

**Non-Goals:** Nest/web; новая навигация таббара; фото профиля; копирование дорисованных CTA/фильтров с макетов; pixel-perfect; новые пакеты/complete-контракты.

## Decisions

### 1. Хаб = A (контент) + B (сетка), без ленты CTA

Порядок скролла для тренера:

1. AppBar: короткое имя.
2. Шапка-карточка: инициалы (не стоковое фото), полное имя, строка абонемента, tint-row ближайшего занятия → `/sessions/:id`.
3. «На этой неделе» + текстовая ссылка «Программа» (если есть `recurringBookingId`).
4. Сетка 2×2 `FyCard` soft: Записать / Назначить / Абонемент / Программа — иконка + подпись, не `FyButton.primary`.
5. «Тренировки» + текстовое «Назначить»; карточки копий (⋯ только если уже есть действия на копии — не выдумывать меню).
6. «Прогресс» как сейчас (чипы + график + старт/сейчас/дельта).

Неделя: клиент режет `upcoming` по текущей календарной неделе (пн–вс локально). Если сессий мало, а серия есть — один `GET` программы серии (уже есть) и показать weekday → title. Без серии и без сессий — пустой баннер, сетка остаётся.

Маршруты сетки (существующие):

| Ячейка | Куда |
|---|---|
| Записать | `/schedule/book-for-student` с предвыбранным учеником (query, если роут уже умеет; иначе тот же экран) |
| Назначить | текущий `assign_plan_sheet` с этим `studentId` |
| Абонемент | `/session-packages` (управление пакетами уже там; не новый CRUD на хабе) |
| Программа | `/schedule/recurring/:id/program` или существующий вход создания серии, если id нет |

Ученик (self): без сетки и без coach-ссылок; шапка + ближайшие + копии + пакет + прогресс.

Альтернатива «только макет A без сетки» отвергнута: пользователь явно склеил A+B. Альтернатива «пять табов как на B» отвергнута (non-goal / уже запрещено спекой).

### 2. Занятие — один primary, остальное текст/overflow

`SessionWorkoutView`:

- Контент: дата/peer/mode, chip «Осталось N», карточка(и) тренировок с компактными рядами и `PlanLoadsTable` как сейчас.
- Под карточкой: `TextButton`/InkWell-ссылки «Изменить состав» · «Сменить» (и «Добавить» / «Убрать» при нескольких workout) — те же `Key`, что сейчас.
- «Программа на неделю»: текстовая ссылка в мета-блоке или пункт ⋯, **не** `FySecondaryButton`.
- Низ (можно `bottomNavigationBar` / sticky padding): `FyButton.primary` «Проведена» при `canComplete`. Пустой план: primary «Выбрать тренировку»; «Упражнения из списка» — текст.
- AppBar ⋯: Неявка, Отменить, История (роль/can*). Подтверждения диалогов без изменения API.

Свести сырые `FilledButton`/`OutlinedButton` на этом экране к `FyButton`. Обёртки `FyPrimaryButton`/`FySecondaryButton` допустимы, если это тот же виджет.

Альтернатива «неявка серой ссылкой под primary как на моке **и** ⋯» — достаточно одного тихого места; предпочтение **⋯**, чтобы не плодить второй ряд. Если ⋯ пуст у студента с одним cancel — показать тихую ссылку «Отменить».

### 3. Компактные теги библиотеки + шит

`PlansLibraryCubit`: сортировка own tags по частоте на загруженных «Мои» шаблонах (и упражнениях в режиме упражнений), tie-break имя. Показ `min(4, n)` чипов + «Ещё», если `n > 4`. Выбранный тег, которого нет в топе, временно вставляется в ряд (чтобы фильтр был виден).

Шит (`showModalBottomSheet`): поиск по имени, список, выбранные чипы, `FyButton.primary` применить (или мгновенный toggle + закрыть — выбрать apply, ближе к моку). Без фильтров «Сложность/Оборудование/Мышцы». Создание тега не дублировать здесь.

Альтернатива SharedPreferences «недавние» — не нужна в v1: частота на текущем списке достаточна.

### 4. `/tags` как группы; delete на хабе

Убрать `IconButton` delete из строки. Карточка: имя, шеврон, строка состава. Состав: после `listTags` — параллельный `GET` hub для видимых тегов (лимит ~15); текст вроде «2 ученика · 3 тренировки». Ошибка hub → карточка без цифр, без блокировки списка. Delete: overflow на `tag_hub_view`.

Альтернатива «менять list DTO» отвергнута (non-goal API). Альтернатива N+1 без лимита — риск; лимит + не грузить отфильтрованные поиском, пока query пустой для всех.

Создание из search field сохранить.

### 5. Макеты — allowlist смысла

Копировать: иерархию блоков, 2×2 сетку, один CTA, компактные чипы + Ещё, шит поиска, карточки тегов без корзины.

Не копировать: 5-tab / «Сообщения» / «Группы» в таббаре, фото, «Смотреть все», difficulty на карточках шаблонов, фоновый экран упражнений в шите.

Токены: существующие `AppColors` / `FyCard` / `FyChip` / `FyButton`.

## Risks / Trade-offs

- [Неделя без программы выглядит пустой] → всё равно показать сессии этой недели; программа — ссылка только при серии.
- [N hub-запросов на `/tags`] → лимит, ignore errors, не трогать API.
- [Абонемент ведёт на общий список пакетов] → приемлемо vs новый экран; шапка хаба уже показывает remaining.
- [Ключи e2e] → сохранить `session-complete`, `session-no-show`, `tag-row-*`; `session-no-show` может оказаться в меню — искать по Key всё равно.
