# План: доработка профиля тренера и каталога

Источник: ревью страницы `#/profile` (мобильный вид). Код: `app/fitness_app/lib/features/social/`, `backend/api/src/social/`. Спеки: `trainer-portfolio`, `trainer-discovery`, `profile-privacy`, `mobile-social`.

## Пункты

| # | Проблема | Решение | Слой |
|---|----------|---------|------|
| 1 | Чипы «Телефон/Telegram/Email» слиплись с подписью «Предпочтительные каналы» | Отступ между подписью и чипами (8–12 px), `Wrap` с `spacing/runSpacing`, отступ от блока Telegram | Flutter |
| 2 | Нет маски телефона | Форматтер `+7 (XXX) XXX-XX-XX`, нормализация к E.164 перед отправкой, валидация длины; на бэке `@Matches` | Flutter + API |
| 3 | Аватар только по https-ссылке | Загрузка с устройства (image_picker + crop/сжатие) → хранилище → `avatarUrl` | Storage + API + Flutter |
| 4 | Портфолио тоже по ссылке | Загрузка фото с устройства; **до 5 работ (записей) в портфолио, в каждой до 5 фото** (два независимых лимита, минимума нет); лимиты на бэке | Storage + API + Flutter |
| 5 | Только город, нет залов | Сущность «зал» (название, точный адрес, город, район текстом), связь тренер↔залы; справочник не ведём — база залов копится из ввода тренеров; поиск тренеров по залу/адресу/району | API + Flutter |
| 6 | Специализации: у ученика «текст с обводкой» обрезан, у тренера нет валидации | Ввод тегами (чипы), лимиты: ≤ 8 тегов, ≤ 30 симв. на тег; у ученика карточка с `Wrap` чипов вместо одной строки | Flutter + API |
| 7 | Редактор портфолио в модалке ломается клавиатурой | Отдельный экран (не модалка) со скроллом и `resizeToAvoidBottomInset`, сетка фото, поля title/description под фото | Flutter |

## Открытые решения (нужны до старта)

1. **Хранилище (п. 3–4) — решено.** MinIO (S3-совместимое) и остаётся: аудитория небольшая, переезд на облако не планируем. `StorageService` за интерфейсом на случай смены, volume + бэкап в docker-compose.
2. **Залы (п. 5) — решено.** Заранее заполненного справочника нет. Тренер вводит название и точный адрес; записи `gyms` создаются из этого ввода, дубли склеиваем по нормализованной паре «название + адрес». Район — текстом, геокодинга нет.
3. **Фото портфолио (п. 4) — решено.** До 5 работ в портфолио и до 5 фото в каждой, без минимума и без связи с публикацией профиля.

## Потоки и зависимости

Волна 1 (параллельно, файлы не пересекаются):

- **A. Flutter UI-полировка** — п. 1, 2 (маска), 6 (UI), 7 (экран портфолио с заглушкой выбора фото). Файлы: `social_profile_editor.dart`, `trainer_profile_screen.dart`, новые виджеты.
- **B. Backend media** — хранилище, `POST /media/upload` (presigned или multipart), лимиты, миграция портфолио (`imageUrl` остаётся), лимит «до 5 фото», docker-compose (MinIO + volume), спека.
- **C. Backend gyms** — сущности/миграция, добавление залов тренером (название + точный адрес, дедуп по нормализации), подсказки по уже введённым залам, фильтр `gymId` / `district` / текст адреса в `/profiles` поиске, валидация специализаций и телефона (п. 2, 6 на бэке), спека `trainer-discovery`.

Волна 2 (после A, одним потоком, т.к. правит те же Flutter-файлы):

- **D. Flutter интеграция** — загрузка аватара/фото портфолио (п. 3–4) поверх B; блок «Залы» в редакторе и фильтр по залу/району в `trainers_page.dart` (п. 5) поверх C.

Финал: прогон на тестовом стенде, ручная проверка `#/profile` на мобильном viewport.
