## Слой A · модель генерации слотов (фикс-сетка)

Тренер задаёт **окно**, приложение берёт **длительность + перерыв** из настроек и нарезает слоты. Пример: окно `09:00–13:00`, длительность `60 мин`, перерыв `15 мин` (шаг 75 мин):

| # | Слот | Статус нарезки |
|---|---|---|
| 1 | 09:00 – 10:00 | ок |
| 2 | 10:15 – 11:15 | ок |
| 3 | 11:30 – 12:30 | ок |
| — | 12:45 – 13:45 | выходит за 13:00 → не создаём |

Параметры:
- Базовая длительность тренировки (напр. 60 мин), возможно разная для online/offline.
- Перерыв между тренировками (опционально, напр. 15 мин).
- Рабочие окна по дням недели + исключения (напр. 25 июля — выходной).

Генератор разворачивает слоты на горизонт (напр. 8 недель), идемпотентен, уважает уже занятые/held слоты, помечает слоты `seriesId` шаблона.

## Слой C · прямая запись тренером на любое время

### Проблема (историческая — закрыта в Слое C)

> Ниже — исходная постановка до `add-coach-book-at-time` / `add-coach-booking-ux`. Поведение уже в проде MVP+schedule.

Тренер видит в календаре свободный слот, но записать в него ученика не может: tap по карточке слота ничего не делает, а экран `CoachBookForStudentScreen` и маршрут `/schedule/book-for-student` существуют без единой ссылки из UI. Единственный доступный тренеру путь записи — принять заявку ученика.

Глубже интерфейса лежит доменное ограничение: `BookSlotParams` принимает только `scheduleSlotId`, поэтому запись возможна лишь поверх уже опубликованного open-слота. Если тренер не сгенерировал доступность на следующий месяц, зафиксировать договорённость с учеником нельзя — система требует сначала опубликовать предложение, которое тренер публиковать не планировал.

### Ключевая мысль

`ScheduleSlot(open)` — это **предложение ученикам**, а `ScheduleSlot(booked) + Session` — **факт занятого времени**. Тренеру, записывающему конкретного ученика, предложение не нужно; ему нужен только факт. Слот должен создаваться как побочный эффект записи, сразу в статусе `booked`. Побочная выгода: open-слот не публикуется ни на миллисекунду, поэтому чужой ученик не может перехватить его заявкой.

Прецедент в коде уже есть — `BookingRequestsService.alternate` в одной транзакции создаёт слот, создаёт Session с charge и переводит слот в `booked`. Нужно вынести это в общий метод с двумя входами: «записать на слот» и «записать на время».

### Принятые решения (Слой C)

| Развилка | Решение |
|---|---|
| Нет слота на нужное время | Создавать слот молча, всегда. Тренеру не мешаем и вопросов не задаём |
| Пересечение с существующей тренировкой | Блокировать и показывать, с чем именно конфликт |
| Входы в создание | Один FAB «+» → лист из 3 пунктов; кнопку «Регулярный график» из AppBar убрать |
| Порядок работ | Сначала change по API (запись на время + автосоздание), затем change по Flutter UX |

### Входы в создание

Три действия различаются тем, с чего начинается фраза: два первых — с **ученика**, третий — со **времени**. Тогда ни один пункт не путается с вкладкой «Доступность», которая и есть график тренера.

| Пункт FAB | Смысл |
|---|---|
| Записать ученика | разово, на дату и время |
| Регулярные тренировки | закрепить ученика за днями недели |
| Свободное время | открыть окно для заявок учеников |

Плюс контекстные входы прямо из календаря: tap по свободному слоту открывает лист «Записать ученика / Записать регулярно / Изменить / Удалить», а tap по пустой строке в дневной сетке — тот же лист с подставленным временем. Второе и есть ответ на сценарий «в сентябре пусто»: тренер листает вперёд, тычет в 18:00 и записывает.

### Конфликты после автосоздания

Автосоздание закрывает ровно одну причину из четырёх, зато самую частую.

| Причина | Что значит | Разрешима автосозданием |
|---|---|---|
| `missing_slot` | времени просто нет в расписании | да, закрывается полностью |
| `held` | слот держит pending-заявка другого ученика | нет, нужно решение по заявке |
| `booked_other` | там уже другая тренировка | нет, нужен перенос |
| `overlap` | пересекается с существующим слотом | нет, нужен перенос |

Уточнение таксономии: сейчас `classifyConflict` возвращает `missing_slot` ещё и когда слот на это время есть, но с другим режимом (online против offline). Это не «нет слота», а конфликт режима, и автосозданием он не решается — на то же время второй слот не создать. Причину стоит выделить отдельно.

Прозрачность вместо вопросов: раз слоты создаются молча, в сводке sync нужен счётчик «создано слотов», чтобы тренер видел последствие, но не был обязан на него реагировать.

### Смежные находки (исторические; часть закрыта в C)

- **Горизонт серии в UI** — закрыто в `add-coach-booking-ux` (поле `horizonWeeksOverride` на create).
- **`POST /schedule/slots` и строгий overlap** — закрыто в `add-coach-book-at-time` (включая `blocked`).
- **Транзакция на occurrence, а не на серию** — осознанный дизайн sync (частичный успех).
- **Согласие с генератором** — book-at-time слоты с `seriesId: null`; генератор пропускает занятое время.
- **Маршруты-сироты** — book-for-student переиспользован из календаря; legacy «Мои слоты» убран из primary path.
