# Суть продукта: Fitness Yoda

## Что это

**Fitness Yoda** — платформа управления тренировками для двух ролей: **тренер** и **студент (клиент)**.

Не маркетплейс «найти зал», а рабочий инструмент связки «тренер ↔ подопечные»:

- запись на занятия (лично и группами);
- календарь и график;
- планы тренировок;
- дневник / история;
- уведомления;
- чат тренера с учениками;
- учёт доходов / кошелёк / фактуры;
- приглашение в систему через QR;
- социальный слой: лента тренеров, отзывы, рейтинг, портфолио, теги, приватность.

На доске роль **тренер** выделена как первичный фокус продукта.

## Проблема

Тренеры ведут подопечных в чатах, таблицах и календарях вручную. Нет единого контура:

- кто записан;
- что было на занятии;
- какой план у студента;
- сколько заработано;
- как быстро добавить нового клиента без «зарегистрируйся сам».

## Ценность

| Для тренера | Для студента |
|-------------|--------------|
| Чат с подопечными внутри приложения | Чат со своим тренером |
| Управление подопечными и расписанием | Удобная запись к своему тренеру |
| Статистика: занятость, доход, график | План тренировок и дневник |
| Фактуры / бухгалтерия / кошелёк | Уведомления о занятиях |
| QR-приглашение клиента | Связь с тренером без поиска «вслепую» |
| Теги для групп и общих планов | Прозрачная история занятий |

## Ключевая механика онбординга

Тренер **кодирует** приглашение (QR / payload) → студент **сканирует / декодирует** → авторизация / регистрация → главная.

Связка «регистрация ↔ авторизация ↔ QR ↔ студент ↔ тренер» — входная точка системы (фрейм «Связи»).

## Что внутри MVP, что позже

### MVP (ядро)

1. Auth: регистрация, авторизация, роли тренер/студент.
2. QR-приглашение и привязка студента к тренеру.
3. График / календарь / занятие.
4. Запись: студент → тренер и тренер → студент.
5. Подтверждение проведённого занятия.
6. История + уведомления (минимум).
7. Базовый план тренировок.

### После MVP — закрыто (уже в продукте)

- Развёрнутая программа тренировок и прогрессия нагрузок (recurring program + session snapshots).
- Абонементы («осталось N», debit на complete / chargeable no_show).
- Лента тренеров, отзывы, рейтинг, портфолио, настройки приватности.
- Ручной учёт оплаты занятия → факт оплаты (`billing-stats`); не эквайринг.
- Теги как группировка людей и видимость планов (базовый контур).

### После MVP — живой backlog

- Чат тренер ↔ ученик (1:1).
- Уведомления по-настоящему (in-app / email / позже push) — в MVP был только минимум.
- Детальная статистика тренера / dashboard (занятость, доход, no-show, пакеты).
- Глубже бухгалтерия: фактуры / баланс («кошелёк») поверх ручных charges.
- Групповые записи (`capacity > 1`).
- Рефералы.
- Design polish: волна B (shell/auth) → C (dark) → D (parked components).

## Границы продукта (пока не делаем)

- Полноценный платёжный шлюз и эквайринг (если не решим иначе).
- CRM зала / многофилиальный gym-management (сущность `Gym` есть в схеме, но это справочник, не ERP).
- Соцсеть общего назначения.

## Рабочее название и тон

- Продукт: **Fitness Yoda**
- Язык UI/доков: русский (как на доске)
- Мобильный клиент — основной; web — дополнительный канал (админка / desktop UX тренера)
