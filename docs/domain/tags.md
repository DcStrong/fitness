# Теги (ярлыки)

Источник: текст рядом с фреймом «Тэги» на Miro.

## Назначение

Теги — это одновременно:

1. **группировка людей** (подопечные / аудитории тренера);
2. **ярлык на плане тренировок**.

Если у студента задан тот же тег, что и у плана — студент **видит** этот план.

Пример с доски: план «Треня на ноги» / «20 приседов по 20 раз» может быть помечен тегом вроде «Ноги».

## Структура тега

Тег состоит из:

1. **Название** — например: `Ноги`, `Спина`, `Пулл-дэнс`
2. **id создателя**
3. **дата создания**

При присвоении своего тега другому пользователю он отображается с ником создателя:

```text
#Ноги#YourLogin
```

## Правила (зафиксировать в реализации)

| Правило | Описание |
|---------|----------|
| Владение | Тег принадлежит создателю (`creatorId`) |
| Уникальность | Уникален в рамках создателя: `(creatorId, name)` |
| Назначение людям | Many-to-many `UserTag` |
| Назначение планам | Many-to-many `TrainingPlanTag` |
| Видимость планов (MVP) | Студент видит план, если (1) активная связь с `ownerCoachId` и (2) пересечение тегов студента и плана **непустое**. План **без тегов** студенту не виден. |
| Содержание плана | Структурированные `plan_exercises` / `plan_sets` плюс `notes` (legacy `body`). Теги не описывают цель — для цели есть поле `goal`. |
| Формат UI | `#Название#Login` при «чужом»/назначенном теге |

## Модель (черновик)

```ts
type Tag = {
  id: string;
  name: string;
  creatorId: string;
  createdAt: Date;
};

type UserTag = {
  userId: string;
  tagId: string;
  assignedBy: string;
  assignedAt: Date;
};

type TrainingPlanTag = {
  planId: string;
  tagId: string;
};
```

## Примеры использования

- Тренер создаёт тег `#Ноги`, вешает на группу студентов и на план «Треня на ноги».
- Студенты с этим тегом видят план в списке доступных.
- Другой тренер не «перехватывает» чужой тег: у него свой `#Ноги#OtherLogin`.

## Вне скоупа MVP (можно отложить детали)

- Публичные глобальные теги без владельца.
- Автотегирование по типу упражнения.
- Иерархия тегов.
