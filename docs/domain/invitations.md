# Приглашения и QR

Источники: фреймы «Связи», «Детальная», «QR».

## Зачем

QR — основной способ, которым тренер приводит студента в систему и сразу связывает его с собой (без «найди меня в поиске»).

## Поток (фрейм «Детальная»)

### Сторона тренера

1. Тренер выбирает / создаёт приглашение для студента.
2. **Кодирование** payload.
3. **Отправка** (показ QR, share link, NFC — см. codec ниже).

### Сторона студента

1. Студент получает / сканирует код.
2. **Декодирование** payload.
3. **Авторизация** (или регистрация, если нового пользователя нет).
4. **Главная страница** уже в контексте связи с тренером.

## Связи модулей (фрейм «Связи»)

```text
        Регистрация
            │
Авторизация ── QR ── Студент
            │
         Тренер
```

QR связывает auth-контур с ролями.

## Codec (из скриншота на фрейме «QR»)

На доске — абстрактная модель кодеков (Dart-стиль):

```text
Codec<Payload>
  ├── QRCode
  ├── Barcode
  ├── Fastag
  └── NFCTag

PersonProfile / EncodedPersonProfile
encode / decode → Future / ByteBuffer
```

Смысл: единый интерфейс кодирования профиля/приглашения, разные транспортные носители. Для MVP достаточно **QR + deep link**; остальные носители — расширение того же `Codec`.

## Рекомендуемый payload приглашения (MVP)

```ts
type InvitationPayload = {
  v: 1;
  invitationId: string;
  coachId: string;
  exp: number; // unix expiry
  sig: string; // подпись сервера
};
```

Клиент показывает QR с URL вида:

```text
<INVITE_HTTPS_BASE>/i/<token>   # например https://app.149.154.64.173.sslip.io/i/<token>, локально http://localhost:8080/i/<token>
```

или `fitnessyoda://invite/<token>`. Настройка домена, App/Universal Links и обновление стенда: `docs/deploy-test-stand.md`, раздел «Ссылки-приглашения».

Сервер хранит:

- `Invitation { id, coachId, status, expiresAt, acceptedByUserId? }`
- одноразовость / TTL — настраиваемо.

## Состояния приглашения

```text
created → accepted
        ↘ expired
        ↘ revoked
```

## Безопасность

- Не класть в QR PII сверх необходимости.
- Подпись / JWT-like token, проверка на бэкенде.
- Rate limit на accept.
- Тренер может отозвать приглашение.
